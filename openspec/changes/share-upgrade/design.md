# 設計

## 資料與狀態
分享卡都由個人裝置依「已在畫面上的資料」產生，不新增儲存、不改 Realtime 邊界。
- 人格卡只接收自己的 `persona` 與 `rare`。純函式先挑出可公開欄位（名稱、金句、稀有度標籤、插圖 key），canvas 只畫這份欄位。
- 團體成功率卡只接收 `score`、`verdict`、`sampleSize` 與日期。函式簽章不收參加者清單、暱稱、人格或配對，隱私由簽章保證，而不是靠呼叫端自律。
- 有效樣本少於兩位時不產生團體卡，不把缺少樣本畫成 0%（沿用既有「單一 complete participant 不得顯示團體成功率」）。

## 呈現
- 人格插圖沿用 `src/assets/personas/` 的既有素材（以 Vite 資產 URL 載入，與頁面同源，canvas 不會被污染）。載入失敗時卡片退回純文字版，不讓分享失敗。
- SSR：整張卡以金色漸層外框與標籤區分，一般卡維持原有深色框。
- 兩張卡共用同一個「系統分享，否則下載」流程；團體卡檔名為 `dinner-group-success.png`。
- 結果頁只在既有分享按鈕旁加一顆「分享團體成功率卡」，且與人格卡一樣只在正式揭曉後顯示。
- 示意結果頁（`?demo=result`）不連資料庫，原本沒有分享按鈕；為了能在無 Supabase 環境驗證，示意頁也顯示分享按鈕並帶入示意成功率。

## 連結預覽
- `index.html` 靜態標籤，不含房號與玩家序號，所有房間連結共用同一份預覽。
- 預覽圖（1200×630）與 favicon 用既有人格插圖合成後放進 `public/`，不使用影像生成。合成腳本放在 `scripts/` 供重現。
- og:image 需要絕對網址，採目前對外網址。

## 實作與驗證
純函式用 Vitest 驗證欄位與隱私（團體卡不得含任何暱稱）；canvas 繪圖用 Playwright 在示意結果頁驗證按鈕、下載檔名、PNG 尺寸；正式流程以 CASE-01 驗證揭曉後才出現按鈕並可下載。連結預覽以 Playwright 檢查 meta 標籤與靜態資源回應。另跑 typecheck、build 與 OpenSpec strict。
